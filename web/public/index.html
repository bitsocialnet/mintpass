Mechanics

How it works

  1. Buy

    Anyone pays for any address

    purchase(to, planId) takes ETH from the payer and mints to to. A user can pay from MetaMask and receive the pass on the address built into their app account. Extra ETH is refunded to the payer in the same transaction; a contract wallet that cannot receive ETH must send the exact quote.

  2. Settle

    The contract prices and forwards

    It reads the Chainlink ETH/USD feed, charges the plan's dollar price, and sends the payment straight to the payout address. Nothing is held in the contract.

  3. Check

    Apps read one number

    balanceOf(address) is 1 while the pass is valid and 0 otherwise. Anything that can read a token balance can honour the pass, with no server in between.

balanceOf(holder) over time

1 0 1
purchase expires renewed

The token still exists after expiry and ownerOf still returns the holder. This departs from ERC-721 on purpose, so existing balance checks respect expiry without new code.

Consumers

What a pass can gate

Built

One holder, one vote

BSIP-18 pubsub voting counts votes from wallets that hold a pass, through its erc5192-min-balance rule. A pass cannot move, so it backs exactly one vote.

Read BSIP-18
Built

Posting without a captcha

Communities that run the EVM contract challenge let pass holders post without solving anything.

evm-contract-challenge
Possible

Whatever you build

Members-only boards, supporter flair, higher rate limits, paid API tiers. If it can call balanceOf, it can check a pass.

Interface

FunctionWhat it does
purchase(address to, uint256 planId) payableMints a pass to to, or renews the one it has. Refunds any excess to the payer.
quote(uint256 planId)The plan's price in wei right now, rounded up.
plans()Every plan: a duration and a price in US cents.
isValid(address)Whether the address holds an unexpired pass.
balanceOf(address)1 while the pass is unexpired, otherwise 0.
tokenOf(address), expiresAt(tokenId)The holder's token id (0 if none) and when it expires.
locked(tokenId)Always true (ERC-5192).
proposePayout(address), acceptPayout()The only privileged action: the payout address hands its role to a new one, in two steps.

Full behaviour, revert conditions, gas numbers and risks are in the README. The contract has not had an external audit.

Fork it

Deploy your own

  1. Fork the repository and add your pass.

    In deploy/config.ts, add your key to the DeploymentKey type, then a name, a symbol and your plans to DEPLOYMENTS. These become immutable, so choose carefully. 

    export type DeploymentKey = "5chan-pass" | "seedit-gold" | "my-pass";

"my-pass": {
  name: "My Pass",
  symbol: "MYPASS",
  plans: [{ duration: 365 * DAY, priceUsdCents: 3000 }],
},

  2. Dry run it.

    The script reads the live feed, simulates the deployment and prints the cost. It sends nothing unless you set DRY_RUN=0. 

    DEPLOYMENT=my-pass PAYOUT_ADDRESS=0x... yarn deploy --network mainnet

  3. Deploy and verify.

    Proceeds go to your payout address from the first sale. A multisig works.

    DEPLOYMENT=my-pass PAYOUT_ADDRESS=0x... DRY_RUN=0 DEPLOYER_PRIVATE_KEY=0x... yarn deploy --network mainnet

  4. Point your app at it.

    Sell it from your own page with quote and purchase, gate on balanceOf, then open a pull request to be listed above.
